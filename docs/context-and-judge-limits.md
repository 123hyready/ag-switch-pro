# 上下文与判断次数

工作模型的上下文容量用于路由候选筛选。选择从供应商获取的模型时，界面填入该模型公布的能力；已保存的旧配置需点击“应用模型能力”更新，刷新列表不会擅自覆盖人工设置。

路由组在 Codex 模型目录中的上下文容量取所有工作模型的最小值，让客户端按共同容量管理历史。这不等于每个工作模型自己的容量。不能把小模型手工填成大模型的容量来扩容。

本次修复为每个路由组单独生成 `auto_compact_token_limit`，设为路由容量的 90%，避免继承模型目录首个模型的压缩点。压缩由客户端发起，代理已有 `/responses/compact` 转发路径；生成阈值通过测试不等于完整长会话压缩已实测成功。压缩后的加密状态仍受原模型归属约束。

“判断次数已达上限（使用回退模型）”原文为“预算耗尽”：达到当前会话的 `maxJudgeCalls` 后，停止调用判断模型，改用回退工作模型继续处理。默认上限 20 次，允许 0–1000；0 表示不调用判断模型。它不是账户余额或 Token 额度。

使用新版本后，在每个工作模型处应用供应商能力，保存路由组并启动客户端路由，然后重启 Codex 以重新加载目录。若仍无法压缩，需要核对实际客户端发出的 compact 请求、响应及相关日志，不能仅凭容量进度条判定原因。
