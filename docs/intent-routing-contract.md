# 意图路由接口约定

路由沿用 cc-switch 的代理协议，新增虚拟模型名称。这里只说明新增行为，不替代已有供应商适配协议。

| 客户端 | 请求入口 | 路由组模型名 |
|---|---|---|
| Codex | `POST /v1/responses`，兼容已有 `/responses` | `ags-group/<groupId>` |
| Claude Code | `POST /v1/messages` | `ags-claude-group-<groupId>` |

客户端继续携带原有请求正文、工具定义、工具结果和流式选项。选择工作模型后，代理替换执行目标模型，沿用原有上游认证、协议适配与响应处理。判断模型只接收有限长度的任务与工具结果摘要，不执行用户任务。

## Codex 官方登录认证

Codex 路由组可以选择未绑定托管账号的 OpenAI Official。判断与工作请求均从当前 Codex 配置目录的 `auth.json` 获取 ChatGPT 登录，遵循已有配置目录覆盖设置。无需重新登录 AG Switch Pro，也不把令牌复制到供应商行或路由组。

令牌在到期前五分钟刷新；刷新保留原文件的未知字段，并原子写回旋转后的令牌。每次调用重新读取文件，程序内串行刷新，写回前比较完整原文件；如果 Codex CLI 已更新、切换账号或退出登录，则采用新状态或拒绝请求，不复活旧登录。跨进程比较与替换之间仍存在很小的竞态窗口，与当前 Magpie/CC Switch 文件登录方案相同。

账号身份与 bearer 同时替换，仅官方路由目标使用原生登录。第三方请求继续使用自己的凭据并剥离 Codex 账号头。已绑定托管账号的官方供应商使用所绑定账号，不回落到原生登录。读取失败、缺少账号、刷新拒绝均返回明确认证错误；不会打印凭据或刷新响应正文。

判断请求适配 ChatGPT 后端：`stream=true`、`store=false`，省略不支持的 `max_output_tokens`，从 SSE 中读取决策与真实用量。模型字段仍须使用实际模型 ID，不能填写界面显示名称。系统钥匙串中没有落盘 `auth.json` 的登录暂未接入；需要 Codex 使用文件凭据。

## 会话与状态

沿用原代理的会话 ID 提取方式。已明确提供会话 ID 才共享判断状态；分支可通过 `x-ag-branch-id` 或 `metadata.branch_id` 区分。带子 Agent 标志但缺少分支身份的请求使用独立状态，避免串用判断。

`previous_response_id`、加密推理或压缩状态需要原目标连续执行。仅已被上游接受执行的工作模型可以成为状态所有者；只有判断结果不能证明状态归属。来源未知时拒绝自动转移。更改路由组配置会推进修订版本并隔离旧状态。

## 判断模型输出

判断模型必须返回一个 JSON 对象：

```json
{"workerId":"cheap","phase":"collect","holdRequests":3,"reason":"读取已知信息"}
```

- `workerId`：代理筛选后的候选工作模型 ID。不存在或不满足能力约束时使用合法回退模型。
- `phase`：建议阶段，例如 `collect`、`plan`、`implement`、`verify`、`diagnose`、`respond`。
- `holdRequests`：包括本次请求在内的保持次数，约束在配置范围内。
- `reason`：简短判断理由。token 数和费用由真实上游用量及本地价格计算，不能由模型自报。

阶段模式在新目标、阶段变化、工具失败或保持次数用完时重新判断。每轮模式在同一用户目标内保持选择。观察模式实际执行默认模型并记录判断建议。固定工作模型和暂停自动路由跳过判断调用。

## 故障与费用

判断调用有超时、会话调用预算和失败冷却。工作模型只有在开始返回响应前遇到可重试故障时才允许进入兼容的回退目标；响应流开始后不重放用户请求。工具、图片、上下文不满足候选要求时不通过丢弃内容来迁就模型。

判断调用进入现有用量账本；即使输出 JSON 无效，已收到的上游用量仍记录。缺少供应商用量或价格时不能宣称费用为零。路由历史只保存模型、阶段、原因和统计，不保存完整任务正文。

## 桌面命令

选择判断或工作模型的供应商后，页面自动调用 `get_intent_provider_models(appType, providerId)` 获取实际模型 ID，提供下拉选择、搜索建议及刷新按钮。相同供应商共享列表请求，切换供应商时忽略过时响应；失败时显示原因并保留原配置。Codex 官方卡复用当前文件登录或绑定的托管账号；API Key 供应商复用现有模型发现服务。其他托管认证类型暂未接入此路由页面的模型发现，会明确提示。

虚拟 Codex 模型目录以项目完整原生 Responses 模板为基础，补齐 `support_verbosity`、截断策略等必填字段；存在基础目录时保留它的自定义字段。上下文最大容量与路由组的保守容量一致，避免空基础目录导致 Codex 启动解析失败。

| Tauri 命令 | 参数与结果 |
|---|---|
| `list_intent_groups` | 返回路由组列表 |
| `save_intent_group` | 输入 `group`，返回服务端更新修订号后的路由组 |
| `delete_intent_group` | 输入 `id`，删除配置并同步已接管客户端的目录 |
| `list_intent_decisions` | 输入可选 `limit`，返回最近路由记录 |
| `simulate_intent_route` | 输入 `group`、`text`，调用真实判断模型，返回试判断结果；不会执行工作任务 |

保存配置不会自动接管客户端。「启动客户端路由」和「恢复直连」沿用既有代理控制命令。尚由 CC Switch 或 magpie 接管的客户端必须先由对应应用恢复直连。

## 验证入口

`tools/Test-Backend.ps1` 调用真实代理 handler，并把上游替换为项目内的 Axum 模拟服务。现有测试覆盖判断复用、模型回退、实际用量解析、模型目录与配置修订；它们证明本地代理行为，不证明外部模型可用性或真实成本节省。
